# 瑪奇 Mobile｜6 角色日週清單

GitHub Pages：<https://nekomata864.github.io/mabinogi-mobile-checklist/>

這是一個純前端、手機友善的六角色清單。未設定同步時，資料會保存在目前裝置的瀏覽器；設定 Google Sheets 同步後，日週進度、材料庫存與交換計畫會寫入既有試算表的「歷史紀錄」，不同裝置可以讀回同一份資料。

## Google Sheets 同步設定

1. 開啟試算表「瑪奇 Mobile｜6角色日週清單」。
2. 選擇「擴充功能 → Apps Script」，將 `Code.gs` 內容貼入並儲存。
3. 在 Apps Script 執行 `setSyncToken()`，輸入一組只給自己使用的密鑰。
4. 選擇「部署 → 新增部署 → 網頁應用程式」：執行身分選「我」，誰可以存取選「任何人」。
5. 複製部署後的 `/exec` 網址，開啟網頁版的「同步」頁，填入網址與同一組密鑰。
6. 每台裝置各設定一次；之後勾選或調整進度會同步，按「從 Google Sheets 讀取」可載入最新資料。

同步 API 只讀取目前遊戲日、本週與「常駐」資料列，舊的「歷史紀錄」不會清除。密鑰只存於 Apps Script Script Properties 與各裝置的瀏覽器設定，不放進公開 GitHub 原始碼。

## Google OAuth 登入版

目前前端已加入 OAuth 原型。OAuth 版直接由 GitHub Pages 呼叫 Google Sheets API，Apps Script 不參與 OAuth 流程；原本的 Token／Apps Script 同步仍保留在「同步」頁的備援區塊。

## Checklist v2 第一階段

目前網頁依最新營運規格整理六角色輪班玩法：

- 新增「六角色總覽」：同頁查看六角色今日與本週必做進度、伺服器共通週任務；今日輪值角色會標示，並可直接跳到指定角色的今日或本週清單。
- 每角色每日清單為兼職、週幾地下城、魔族供品與普通黑色坑洞今日基本獎勵。今日坑洞勾選會計入該角色週進度，從本週頁第一次增加坑洞也會標記今日；同一份獎勵不需填兩次。
- 採購及交換依具體商品／路線追蹤，不顯示泛用日／週確認勾選。舊版泛用紀錄仍可匯入，不影響現在完成率。
- 舊的角色坑洞標記會留在相同角色；舊帳號共通勾選沒有角色資訊，不會自動計入任何角色。
- 兼職只記錄是否處理，不區分聖水、高價值或普通；星期一會顯示「週初：建議六角色優先清理兼職庫存」提示。
- 每週頁依角色顯示結界、普通坑洞、野外首領、小格與深淵；白魅魔只列本尊。小格目標為本尊困難／分身入門；深淵為本尊可打的最高難度／分身單人地獄1，各 3 次。伺服器共通週任務只需完成一次。
- 泛用的生活材料與討伐證明週採購不再作為角色週任務 checkbox；具體可追蹤商品只列於「採購」頁，週日補漏會列出尚未完成的具體商品數量。
- 不詳的召喚結界改為 `0 / 7` 箭頭計數；每角色每週 7 次獎勵，達到 7 次後視為完成。既有 LocalStorage／Sheet 次數資料可直接延續。
- 普通黑色坑洞依角色追蹤每週 14 次；韓服官方指南列每日基本 1 次、每週超額 7 次，未用的每日額度次日 06:00 消失。戰利品箱消耗既有獎勵次數，不能補回過期額度；台服角色範圍請依遊戲畫面覆核。
- 野外首領週戰利品與格里斯貝恩（小格）都是每角色每週 1 次；同一角色選哪一隻野外首領都只算一次。
- 分身深淵依單人地獄1目標計入每週必做；白魅魔只要求本尊單人完成，不會在分身清單或週日補漏中出現。
- 新增「今日主角色」輪班提示：週一至週六依序為貓又老師、貓又老師z、貓又老師zz、貓又老師o、貓又老師p、貓又老師oo；週日顯示六角色週課總盤點，提供補漏摘要。
- 新增「特殊事件」區塊：通往深淵的黑色坑洞只作看到就打的提示，不計入 Daily／Weekly 完成率，也不寫死尚未被官方確認的等級條件。
- 採購／交換頁保留原本地區、NPC、商品、Cost、Daily／Weekly、角色／帳號 Scope、證據等級與來源；追加 9/9 官方更新中有明確限制的班克爾及 NPC 商店／交換項目。

採購頁在兩種最高級材料預設每角色本週計畫 30，可自行調整為 0–30；其餘週商品預設未規劃，不把限額視為必買量。六角色巡店顯示已買、計畫量與上限，週日只列已規劃但未完成的品項。班克爾黃豆換肉、魚湯換銀合金錠，以及韓服舊木材／催化與艾明馬夏玩家候選路線均標示來源與待核對狀態。

LocalStorage 的舊角色任務索引會在既有週版面遷移後，一次搬到穩定任務 ID；舊 key 保留作相容備份。Sheets 匯入會把既有任務名稱與別名對應到相同 ID，寫入仍沿用現有任務名稱與 `歷史紀錄` 欄位。採購計畫以 `採購計畫｜商品 ID` 寫入既有週紀錄。不清除舊資料，也不需改表頭；帳號共用資料仍以 `角色=帳號共用` 記錄。

啟用前需要完成：

1. 在 Google Cloud 建立 OAuth consent screen。
2. 建立 Web application OAuth Client ID。
3. 啟用 Google Sheets API。
4. 將 `https://nekomata864.github.io` 加入 Authorized JavaScript origins。
5. 將需要使用的 1～2 個 Google 帳號加入測試使用者，並把同一份試算表共用給這些帳號。
6. 修改 `index.html` 頂端的 `GOOGLE_OAUTH_CLIENT_ID`。
7. 如需前端帳號白名單，填入 `ALLOWED_GOOGLE_EMAILS`；真正的資料權限仍由 Google Sheet 的共用權限控制。

OAuth Client ID 可以公開放在前端，但不要把 Client Secret、Access Token 或其他密鑰提交到 Repository。Access Token 只在目前頁面的記憶體中使用，重新整理頁面後需重新登入或授權。

OAuth 讀寫沿用既有「歷史紀錄」欄位與資料規則，並以 `重置日 + 角色 + 任務名稱 + 週期` 找到既有列；找不到時才新增資料列，不會清除歷史紀錄。

## 採購頁資料範圍

目前可追蹤的採購項目以台服已核對的限購、NPC 商店與交換為主，包括班克爾的料理／加工交換、銀合金錠、最高級生皮／最高級蜘蛛網、魔力石、杜巴頓每週商店、提爾克那討伐證明商店等。採購列會以 `任務名稱=採購｜項目 ID` 寫入同一張「歷史紀錄」，不需要新增欄位。

採購頁已改為用途導向分類，不再提供泛用的「全部」頁面；開啟採購時預設先看「稀缺優先」：

- 「稀缺優先」：最高級生皮、最高級蜘蛛網，以及 65 等級以上角色的礦山／曠野魔力石。這些有明確限購或長期材料價值，優先檢查。
- 「料理常備」：肉、鹽、高麗菜、胡椒、糖、蘋果、大蒜、檸檬、食用油、蛤蜊。這些是公開 Tracker 配方中反覆出現的基礎材料，適合依共享倉庫與料理計畫巡店，但不是六角色固定週目標。
- 「需求補買」：番茄、蘆筍、豌豆、草莓、冰。用途較集中或舊 Tracker 價格較高，只有準備製作對應料理時才購買。
- 「每日限購」：已確認的角色／帳號每日交換與商店項目，仍使用既有勾選或數量 Stepper。
- 「每週限購」：已確認的角色／帳號每週商店與交換項目，仍依商品的 Scope 分開記錄。
- 「材料參考」：一般生皮與食材店候選商品等資訊列，只作查詢，不列入完成度，也不寫入 LocalStorage／Google Sheets。

採購頁的分類說明與資料來源已移到清單下方的可展開區，避免上方佔用手機畫面。頁面仍保留地區、NPC、商品、Cost、Daily／Weekly、角色／帳號 Scope、證據等級與來源。

食材店目錄目前收錄 15 個候選商品：肉、鹽、高麗菜、胡椒、糖、番茄、蘆筍、豌豆、食用油、蘋果、大蒜、檸檬、草莓、蛤蜊、冰。這些資料用於「料理常備／需求補買」分類與配方用途判斷；公開 Tracker 的舊價格、庫存數、城鎮／NPC 位置與刷新週期均標示為待核對，不直接當成台服規則。

頁面參考台服官方更新、台服玩家整理、公開料理 Tracker 與多用途材料清單；非官方資料只作採購建議，不會自動變成六角色必買任務。實際購買前仍以台服遊戲內商店顯示為準。

## 六倉庫存與交換缺料估算

- 「倉庫」頁目前可登記 18 種以物易物投入材料；每項可指定主要保管角色並輸入該角色的數量，頁面同時顯示六倉合計。
- 「採購」頁的交換路線卡可加入帳號計畫次數。系統會把已排路線的材料需求加總，扣除六倉合計後列出缺料量；只計算資料列明確標示的「材料 × 數量」，未標數量的金幣／條件不推估。
- 缺料結果是採集與交換規劃估算。請只把能實際轉移並可用於該路線的庫存列入，並以台服遊戲內交換條件核對社群路線。
- 庫存列使用 `週期=常駐`、`重置日=永久` 與 `任務名稱=庫存｜材料 ID`；保管角色記在 `庫存保管｜材料 ID`，路線計畫記在 `路線計畫｜路線 ID`。資料都沿用現有「歷史紀錄」欄位，不改表頭、不清理舊資料。
- OAuth 同步已支援常駐資料。若使用 Token／Apps Script 備援，請把最新版 `Code.gs` 貼到 Apps Script，將現有網頁應用程式部署為新版本；舊版腳本不認得「常駐」週期，會拒絕新的庫存與計畫寫入。
