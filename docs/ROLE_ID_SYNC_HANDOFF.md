## 下次討論網站或轉職時先提醒

1. 先明確告知使用者：`Code.gs` 的新版已在 GitHub，但實際 Apps Script 部署仍待核對；詢問是否已由使用者手動更新，並依可取得的證據驗證。不要假設已完成。
2. 若尚未部署：從正式 Sheet 的「擴充功能 → Apps Script」檢查現有專案檔案，避免覆蓋其他自動化。更新同步程式後，透過「部署 → 管理部署作業 → 編輯現有部署 → 新版本 → 部署」，沿用原 `/exec` URL。無須索取密碼、Token 或密鑰。
3. 部署後測試讀取與寫入，確認 `zz` 與 `o` 分別寫入各自的 ID、進度與庫存不錯位，並確認舊資料仍能讀回。可在安全範圍內用現有進度做可還原的驗證。
4. 之後轉職只變更職業顯示、符文與操作指南。若要清理 Sheet 的舊名稱或重新命名角色分頁，先盤點外部 Apps Script／公式依賴並另做遷移；不要直接批次取代 `歷史紀錄!B:B`。
5. 完成實際部署及驗證後，更新本文件的狀態，避免反覆提醒已解決的事項。

此提醒只在相關修改／轉職討論時提出，不需定期追蹤。
